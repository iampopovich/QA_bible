# Вычитка (пруфчекинг)

Автоматического спеллчекера в проекте нет: вычитка выполняется человеком или агентом по этому
документу. Цель — грамотный, единообразный и фактически верный текст без изменения смысла.

## Порядок вычитки страницы

1. **Факты** — определения, цифры, утверждения о поведении инструментов сверены с источником из
   `## Источники` или с официальной документацией. Неподтверждённое — убрать или найти источник.
2. **Термины** — по таблице ниже; одинаковые понятия названы одинаково на всей странице.
3. **Орфография и пунктуация** — нормы русского языка; англоязычные фрагменты — нормы английского.
4. **Типографика** — правила S-07 (тире), S-08 (кавычки), S-06 (списки) из `style-guide.md`.
5. **Ссылки** — текст ссылки осмысленный, ссылка ведёт туда, куда обещает (см. `integrity.md`).

Агент при вычитке исправляет только явные ошибки. Стилистическую переработку, сокращение и
перестановку материала — делать отдельным коммитом и описывать в PR.

## Частые ошибки в книге

| Неправильно | Правильно | Комментарий |
|---|---|---|
| тест кейс, тесткейс | тест-кейс | также: чек-лист, баг-репорт, тест-план |
| не правильно, не корректно (наречия) | неправильно, некорректно | слитно, если нет противопоставления |
| в следствии, в течении (времени) | вследствие, в течение | |
| что бы (союз) | чтобы | раздельно — только «что бы ни…» |
| так же (в значении «тоже») | также | |
| Javascript, Github, Postgres | JavaScript, GitHub, PostgreSQL | официальное написание продуктов |
| АПИ, апи | API | аббревиатуры латиницей |
| е вместо ё в новом тексте | ё | в старом тексте массовую замену не делать |
| «-» вместо тире | « — » | дефис только внутри слов |
| "кавычки", “кавычки” | «кавычки» | вложенные — „лапки“ |

## Термины

Принятое написание; при первом упоминании на странице — русский вариант и английский в скобках.

| Термин | Пишем | Не пишем |
|---|---|---|
| bug | баг, дефект (в определениях ISTQB) | бага, ошибка (если речь о дефекте) |
| test case | тест-кейс | тесткейс, тест кейс |
| checklist | чек-лист | чеклист |
| flaky test | flaky-тест (нестабильный тест) | флаки, флейки |
| smoke testing | smoke-тестирование (smoke testing) | дымовое тестирование, смоук |
| regression testing | регрессионное тестирование, регресс | регрессия (о тестировании) |
| CI/CD | CI/CD | ci/cd, СИ/СД |
| pull request | pull request (PR) | пулл-реквест |
| framework | фреймворк | фрэймворк |
| requirements | требования | реквайрменты |

Список пополняется по мере вычитки: если на двух страницах один термин написан по-разному — выбрать
вариант, внести в таблицу и привести страницы к нему.

## Чего не делать

* Не менять смысл, не «улучшать» определения ISTQB — это цитаты.
* Не переводить названия продуктов и общепринятые англицизмы (smoke, flaky, CI/CD).
* Не трогать текст внутри блоков кода и inline-кода, URL и якоря.
* Не делать массовые автозамены по всей книге без вычитки дифа.
